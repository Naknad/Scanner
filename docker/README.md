# Своё Вино — Сканер этикеток (MVP, OCR)

MVP-реализация модуля распознавания вина по фото этикетки для платформы
«Своё Вино» (кейс РСХБ «Цифра»). Текущая версия — **OCR-based**: без обучения
CV-моделей, чтобы быстро получить работающий end-to-end пайплайн
(загрузка фото → распознавание → карточка вина в JSON). Архитектура
рассчитана на последующее добавление CV-эмбеддинга (см. `ARCHITECTURE.md`).

## Состав

```
docker/
├── docker-compose.yml
├── backend/
│   ├── Dockerfile
│   ├── requirements.txt
│   ├── app/            # FastAPI-сервис: OCR, матчинг, API, отдача фронтенда
│   └── data/

└── scripts/
    └── eval_client_example.sh
```

## Запуск

Требуется Docker + Docker Compose. Работать полностью локально, без внешних
сервисов (никаких GPU/облачных ключей для MVP не требуется).

```bash
cd docker
docker compose up --build
```

Сервис поднимется на `http://localhost:8000`.

- `http://localhost:8000/` — веб-интерфейс (загрузка фото / камера).
- `http://localhost:8000/api/health` — проверка, что каталог загружен.

## Загрузка реального каталога

Положите файл дампа (CSV или JSON, как описано в ТЗ) в `backend/data/`
и укажите путь через переменную окружения `CATALOG_PATH`
(по умолчанию `/app/data/catalog.csv`, монтируется через volume — пересборка
образа не нужна, достаточно `docker compose restart`).

Ожидаемые (гибко сопоставляемые по алиасам, см. `app/catalog.py`) поля:
`slug, name, producer, region, grape, category, color, vintage, description,
roskachestvo_score, public_rating, abv, serving_temp, food_pairing, image_url`.
Поле `food_pairing` — список через запятую/точку с запятой в CSV
(например `"Красное мясо, стейк, твёрдые сыры"`).
Если реальный дамп называет колонки иначе — расширьте словарь `ALIASES`
в `backend/app/catalog.py`, остальной код менять не нужно.

## Переменные окружения

| Переменная            | По умолчанию              | Назначение                                             |
|------------------------|----------------------------|---------------------------------------------------------|
| `CATALOG_PATH`         | `/app/data/catalog.csv`    | Путь к дампу каталога (CSV/JSON)                        |
| `OCR_LANGS`            | `rus+eng`                  | Языки Tesseract                                          |
| `MATCH_MIN_SCORE`      | `55`                       | Порог уверенности top-1 (0–100), ниже — "не найдено"     |
| `MATCH_GAP_THRESHOLD`  | `8`                        | Требуемый отрыв top-1 от top-2, ниже — статус `ambiguous`|
| `TOP_K`                | `5`                        | Сколько кандидатов возвращать в `top5`                  |

## API

- `POST /api/scan` — multipart `file`, полный ответ для UI: карточка, топ-5,
  метрики уверенности, время ответа.
- `POST /api/predict` — multipart `file`, **плоский JSON `{"slug": "..."}`**
  для скрипта оценки кейсодержателя.
- `GET /api/card/{slug}` — карточка вина по слагу (для шаринга/прямых ссылок).
- `GET /api/sommelier/{slug}?dish=...&occasion=...` — MVP «Цифрового сомелье»
  (фича удержания после поиска, правило-ориентированная на MVP-этапе).
- `GET /api/health` — статус сервиса и размер загруженного каталога.

Проверка совместимости со скриптом кейсодержателя:

```bash
./scripts/eval_client_example.sh /path/to/public_dataset
```

## Известные ограничения MVP

- Матчинг — классический fuzzy string matching по OCR-тексту (без
  CV-эмбеддингов). На сильно смазанных/повёрнутых фото или при полном
  отсутствии текста на этикетке (только графика) качество будет ниже, чем у
  комбинированного CV+OCR решения — это осознанный компромисс ради скорости
  поставки MVP.
- Пример каталога (`backend/data/catalog.csv`) — 5 демо-позиций для
  проверки пайплайна. Перед оценкой обязательно подставьте реальный дамп.
- Стилистика и набор полей карточки (регион, сорт, категория и цвет,
  температура подачи, крепость, народный рейтинг, сочетание с блюдами)
  сверены со структурой реальной карточки товара на vino-svoe.ru. Точные
  hex-цвета/шрифты/иконки бренда автоматически вытянуть не удалось (нет
  доступа к CSS сайта из этого окружения) — сейчас использована близкая по
  духу светлая палитра с винно-бордовым акцентом. Пришлите бренд-гайд/скрин
  или экспортированные CSS-переменные, если нужно попадание тон-в-тон.
- «Цифровой сомелье» на MVP-этапе работает по правилам поверх полей каталога,
  без вызова LLM (чтобы не тянуть внешние API-ключи в MVP). Точка расширения
  описана в `ARCHITECTURE.md`.
